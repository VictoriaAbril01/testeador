# Auditoría integral del MVP de TestLab

Fecha: 12 de octubre de 2026 (America/Mexico_City). Alcance: fases 2 a 5 y flujo frontend → FastAPI → PostgreSQL → Redis/RQ → Playwright → analizador → evidencias → reporte. Esta auditoría no modifica funcionalidades.

## Criterio y estado del repositorio

**COMPLETO** significa implementado y probado; **PARCIAL**, implementado con una limitación o sin verificación suficiente; **PENDIENTE**, ausente; **BLOQUEADO**, dependiente de una decisión o infraestructura externa. Una prueba de archivo, clase o endpoint aislado no equivale a demostrar el flujo.

Se inspeccionaron `AGENTS.md`, `docs/roadmap.md`, `docs/requirements.md`, `docs/architecture.md`, configuración, migraciones, modelos, API, frontend, tester, workers y pruebas. `git status --short` mostraba todo el proyecto como archivos sin seguimiento (`??`), sin commit de referencia. No hay cambios previos rastreados con los que comparar ni se hizo commit. La instalación auditada usa Docker Compose para API, PostgreSQL, Redis y worker; la cola de la configuración ordinaria está desactivada (`queue_enabled() == False`).

### Prueba real de extremo a extremo

Se levantó una aplicación HTTP de prueba aislada en la red de Docker con login, página sana, excepción JavaScript, HTTP 500 y enlace HTTP 404. Un worker **privado temporal**, separado del público y restringido a la IP exacta de esa aplicación (`172.26.0.6/32`), ejecutó el ensayo. La API se recreó temporalmente con la cola habilitada. Desde la interfaz en Chromium se introdujo la clave de operador, se creó el proyecto, se configuró un acceso de prueba cifrado y se solicitó la ejecución. No se probó ningún destino ajeno.

- Proyecto: `905ed284-76ae-4351-ad96-210acc5ebfab` (`Auditoría MVP local 2026-10-12`). Primera ejecución: `104eca25-96f6-4dcc-9012-d0663a3890c1`, estado `completed`.
- La ejecución persistió **7 páginas, 11 pasos, 3 hallazgos y 15 evidencias**: `http_5xx` en `/server-error`, `broken_link` en `/broken` y `javascript_error` en `/js-error`. No hubo hallazgo en `/healthy`. Los pasos registraron login y navegación. El worker RQ procesó el trabajo y terminó sin dejar navegador abierto.
- Cada hallazgo tuvo captura PNG, log de consola, metadatos HTTP, traza de navegación e historial de pasos. Los 15 archivos se descargaron por API autenticada; coincidieron con los SHA-256 guardados, sumaron 21.591 bytes y respondieron con `Cache-Control: no-store`. No contenían los valores de prueba usados como contraseña, usuario o cookie. La columna de credenciales en PostgreSQL contenía texto cifrado.
- La interfaz abrió el detalle, mostró las 5 evidencias de un hallazgo, cargó la imagen y descargó JSON. El reporte HTML se descargó desde la interfaz y la API (HTTP 200, 4.810 bytes, adjunto); no contenía el secreto de prueba. Se confirmó manualmente el HTTP 500 sembrado; quedó una entrada de validación con actor `operator`.
- Se inició el retest desde la interfaz: `0dd27f57-1e12-44c3-aaf3-d20cd7894126`, estado `completed`, 3 hallazgos. La comparación API y la interfaz mostraron **3 persistentes**, con 5 evidencias anteriores y 5 nuevas por hallazgo. El historial de la huella del HTTP 500 reunió ambas ejecuciones. La consola de la página de TestLab no mostró errores durante el recorrido comprobado.
- La captura revisada del hallazgo quedó prácticamente blanca: la política CSS oculta todo el texto y la aplicación de prueba era esencialmente texto. Se demostró captura, almacenamiento y descarga, pero **no utilidad visual suficiente** para esa página.

El worker privado, la aplicación de prueba y Vite se detuvieron. API y worker públicos se restauraron con Compose; `queue_enabled() == False` y no quedaron contenedores temporales. Las filas de proyecto/ejecución y sus evidencias permanecen en la base y el volumen de desarrollo para inspección manual; la retención normal de evidencias es de 30 días. Las pruebas unitarias usan transacciones reversibles. No se alteró `.env`.
